# Recipe-Analysis-Report

CVD（化学气相沉积）工艺分步分析报告生成器。

输入 **recipe（工艺配方）+ log（设备运行数据）两份 Excel**，输出**单文件交互式 HTML 报告**——
Plotly.js 已内联，双击即可离线打开，不需要服务器、不需要联网。

---

## 功能

对单炉次的一次完整工艺，按 step 自动切分（升温 / 恒温 / 降温），逐步给出：

- **温度变化速率**：分段最小二乘拟合，输出 ℃/min 及拟合优度
- **功率升降速率**：功率模式步给出 kW/min（正 = 提升，负 = 下降）
- **真空—蝶阀变化速率**：Pa/min、°/min，含突跳与平台识别
- **曲线类型判定**：单一线性 / 多段线性 / 前期线性+后期平台 / 波浪式 / 全程平台停滞 / 短步
- **一行结论摘要**：把速率、类型、达标情况合成一句可直接引用的中文结论

图表部分给出全程双轴总览图（温度 + 功率 / 真空 + 蝶阀）与逐点可交互曲线，
按步切换查看，支持对数轴与抽稀（保留极值，峰值谷值不会被抹掉）。

## 环境

- Python 3.9+（实测 3.13）
- Windows 10/11（双击模式依赖系统文件选择框；其它平台用命令行）

```bash
pip install -r requirements.txt
```

可选加速：`pip install python-calamine`。log 通常有上百列、数万行，用 Rust 实现的 calamine
解析比 openpyxl 快约 8 倍；装了自动启用，没装自动回落。

解释器定位顺序：环境变量 `CVD_PY` → 项目内 `.venv\Scripts\python.exe` → `PATH` 里的 `python`。
依赖装在哪个解释器里就让它被找到，双击即可直接跑。

## 首次使用（新机器 / 刚从仓库 clone）

仓库**只含源码，不含数据与产物**（`输入/`、`输出/`、缓存都被 `.gitignore` 排除）。三步即可：

```bash
pip install -r requirements.txt                                    # 1

python make_report.py --recipe "D:/任意位置/29C261016-recipe.xlsx" \
                      --log    "D:/任意位置/29C261016-log.xlsx"     # 2
```

3. 报告输出到 `<项目根>\输出\需求10_交互式HTML报告\`；要另存加 `--out <目录>`（目录不存在会自动创建）。

几点说明：

- **数据放哪都行**——绝对路径、相对路径、带空格或中文的目录都支持，不必放进项目里。
  想用双击模式，把文件放进 `输入/recipe/`、`输入/log/` 会更省事（对话框会直接定位过去）。
- **批次名（炉次号）**：优先从文件名里识别 `29C26xxxx`，其次取 recipe 的 **sheet 名**
  （现场常出现文件名被改成「配方 最终版」而 sheet 名仍是炉次号）；两者都没有时，
  报告会标成「未命名批次」并提示，用 `--name 29C261016` 指定即可。
- **老批次模式**（`make_html_report.py run1`…`run6`）复用需求3/4/6 的历史产物，
  新克隆的仓库里没有这些文件，直接跑会给出替代命令提示——单批次请用上面的 `make_report.py`。
- **输出目录不用手动建**。首次运行会自动创建 `输出\需求10_交互式HTML报告\`。

## 用法

### 双击运行

双击 `make_report.bat`，在弹出的两个选择框里依次选 recipe、log，确认批次名后自动生成并打开报告。

### 命令行

```bash
# 最简：只给文件名（会自动在生成器目录下查找）
python make_report.py --recipe 26C010101-recipe.xlsx --log 26C010101-log.xlsx

# 也可以给任意位置的完整路径
python make_report.py --recipe D:/downloads/batch-recipe.xlsx --log D:/downloads/batch-log.xlsx

# 指定标题与工况备注
python make_report.py --recipe ... --log ... --name 26C010101 --note 中阻

# 只生成不打开、指定输出目录、强制重算
python make_report.py --recipe ... --log ... --out D:/tmp --no-open --no-cache
```

| 参数 | 说明 |
|---|---|
| `--recipe` | 配方 Excel 路径（可只给文件名；省略则弹窗选择） |
| `--log` | 运行数据 Excel 路径（可只给文件名；省略则弹窗选择） |
| `--name` | 批次名，用作报告标题；默认从文件名中提取 `\\d{2}C\\d{6}` 形式编号 |
| `--note` | 工况备注，显示为副标题（如 `中阻`、`不同转速`） |
| `--out` | 输出目录，默认写入项目内的报告目录 |
| `--sheet` | 手工指定配方工作表名 |
| `--no-open` | 生成后不自动打开 |
| `--no-cache` | 不复用数据抽取缓存 |

> 给 Windows 的 Python 传路径时用 `C:/...` 或 `C:\\...`，不要用 MSYS 风格（`/c/...`）。

## 输入数据要求

### recipe（配方）

- 读取**第一个包含「步号」列的工作表**（文件名与 sheet 名经常不一致，因此不按名字猜）
- 需包含：步号、时长、目标温度、功率设定、真空/蝶阀设定、各路气体流量

### log（运行数据）

- 单个工作表
- 原始表通常有上百列，本工具只取其中 13 列。**必需列**：
  `时间`、`当前运行步号`、`T1温度`、`T2温度`、`主控温度`、`电源总功率反馈`、`炉内真空`、`数控蝶阀开度反馈`
- 选读列：`目标温度`、`PID目标温度`、`目标压力`、`高真空反馈`、`低真空反馈`
- 连续采样记录（分钟级/小时级均可，需覆盖整个工艺段）

## 输出

一个 `.html` 文件（约 6–7 MB，含内联图表库与逐点数据）：

- 顶部 KPI：步数、时长、总升温/降温、峰值温度
- 逐步列表：步号、阶段、温度模式、推荐速率、结论摘要、达标判断
- 每步两张图：温度—功率双轴、真空—蝶阀双轴，附拟合段与注释

邮件附件偏大，分发建议走共享盘。

## 计算口径

几处容易算错的地方，已在实现中固定：

1. **温度通道选择**：若两路热电偶在「重叠测温窗」（T1 未饱和 且 T2 有效）内的
   `|T1−T2|` 中位数 < 30℃，视为同一测点的双量程，按量程拼接使用；否则视为不同测点，
   保留控制器主控温度原值，仅修复高温冻结伪影。**不能用全量中位数判断**——
   低温段 T2 未起测、高温段 T1 饱和，会把所有批次误判。
2. **短步不出速率**：有效采样点少于 12 个的步不给推荐速率，否则几分钟的步会算出上百 kW/min 的伪斜率。
3. **平台话术分域**：温度—功率与真空—蝶阀共用同一套分段模型，但平台类型分别表述为
   「恒温」与「恒压」，字面量集中在一处定义，避免混用。
4. **结论按实际数据生成**：不写死步号与数值，图文口径始终与当次计算结果一致。
5. **抽稀保留极值**：降采样时对极大/极小点做保护，峰值、谷值、突跳不会被抹平。
6. **HTML 主控线用 log 原始值**：需求7/方案C 的 T1/T2 拼接值只用于速率、终点与判定，
   不替代图中的「主控温度」——否则源主控在 T1 饱和段的冻结/通道切换会被画成一段线性上升。
   图下注释给出该步的拼接值区间；源主控 0/负值缺测点一律断线。

## 模块职责

| 模块 | 职责 |
|---|---|
| `batch_pipeline` | 单批次流水线：串起读盘、切段、判型、汇总、渲染，对外 API |
| `make_html_report` | 报告渲染：把计算结果与曲线渲染成单文件 HTML |
| `analyze_v5` | 主工艺段切分、pass 轮次标注、逐步汇总 |
| `analyze_process_v3` | 温度—功率：分段最小二乘拟合与曲线类型判定 |
| `analyze_vacuum_v4` | 真空—蝶阀：同框架，话术切换到压力域 |
| `analyze_v6` | 逐步结论摘要合成 |
| `temp_fix` | 温度通道一致性判断与量程拼接 |
| `seg_terms` | 分段类型话术（温度域 / 压力域） |
| `recipe_meta` | 配方缺步检测（配方有时长、数据无记录） |
| `batch_notes` | 人工干预记录，避免被误判为控制异常 |
| `project_paths` | 路径解析，项目根可用环境变量覆盖 |

### 对外 API

```python
import batch_pipeline as bp

recipe, rinfo = bp.load_recipe_any("recipe.xlsx")   # 自动定位含「步号」的工作表
proc,   linfo = bp.ingest_log("log.xlsx")            # 切分主工艺段 + 温度口径
step_df, segT_df, segV_df = bp.analyze_batch(proc, recipe, tag="batch01")

html_path = bp.generate("recipe.xlsx", "log.xlsx", name="batch01", note="中阻")
```

`analyze_batch()` 返回三张表：步汇总表、温度分段明细、真空分段明细，
均为 pandas DataFrame，可直接落 Excel 或二次计算。

## 已知限制

- 只覆盖主工艺段，装炉 / 抽真空 / 回温等辅助段不进入分步统计
- 双击模式仅 Windows 可用
- 报告为单文件内联，体积随步数与采样密度线性增长
